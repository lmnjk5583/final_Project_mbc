### 1.1 목적

본 계획서는 고속도로 CCTV 영상 기반 이상징후 탐지 시스템(이하 '본 시스템')의 안정적인 운영을 위한 절차, 담당 역할, 대응 기준을 정의한다. 역주행 차량 탐지 및 교통 정체 모니터링 두 가지 핵심 기능의 운영 지침을 포함하며, 시스템 배포부터 일상 운영, 장애 대응, 성능 개선에 이르는 전 단계를 망라한다.

## 2. 시스템 구조 및 구성요소

### 2.1 시스템 아키텍처

본 시스템은 CCTV 영상 수집부터 이상징후 탐지, 운영자 알림, 사후 분석까지의 전 과정을 자동화한 파이프라인으로 구성된다.

| 단계 | 구성 모듈 및 역할 |
|------|-----------------|
| ① 영상 수집 | 고속도로 CCTV 카메라 → VideoCapture (OpenCV) → 프레임 스트림 분리 |
| ② 객체 탐지 | YOLO11n (best.pt) — 차량 바운딩 박스 감지, 클래스: 승용차/트럭/버스/이륜차 |
| ③ 객체 추적 | ByteTrack (bytetrack.yaml) — 프레임 간 ID 연속성 유지, 사라짐·재등장 처리 |
| ④ 흐름 학습 | Flow Map (20×20 Grid) — 정상 교통 방향 벡터 EMA 학습, 이중 선형 보간 제공 |
| ⑤ 역주행 판정 | Judge — 코사인 유사도 + 투표 + 히스테리시스 3단계 판정, W1/W2 라벨 부여 |
| ⑥ 정체 분석 | Traffic Analyzer — 속도·밀도 집계, SMOOTH/SLOW/CONGESTED 분류 |
| ⑦ 시각화·알림 | Visualizer (OpenCV) + 대시보드 SCR-01~09 + 모바일 Push 알림 |
| ⑧ 로깅 | CSVLogger — frame_log.csv / track_log.csv / events_log.csv (run_YYYYMMDD_HHMMSS/ 폴더) |

> ⚠️ config.py 실제값: `grid_size=20` (문서 원본 15×15에서 수정)

### 2.2 동작 모드

시스템은 다음 3가지 모드를 순서대로 전환하며 운영된다.

| 모드 | 지속 시간 | 설명 |
|------|---------|------|
| **LEARNING** | 약 60초 | 영상 앞 1800프레임(≈60초@30fps) — 정상 교통 흐름 학습. 학습 완료 시 flow_map.npy 저장. |
| **DETECTING** | 상시 | 역주행 탐지 + 교통 정체 모니터링 실행. Online Flow Update로 흐름맵 점진적 갱신 가능. |
| **RELEARNING** | 약 10초 | 카메라 전환 감지 시 자동 진입. 300프레임 재학습 후 150프레임 쿨다운 → DETECTING 복귀. |

> ⚠️ config.py 실제값: `learning_frames=1800` (문서 원본 500프레임에서 수정)

### 2.3 주요 파라미터 기준값

| 파라미터 | 기준값 | 허용 범위 | 의미 |
|----------|--------|---------|------|
| **learning_frames** | **1800** | 100~3000 | 초기 학습 프레임 수 |
| **cos_threshold** | **-0.75** | -1.0~0 | 역방향 판정 기준 |
| **wrong_count_threshold** | **8** | 1~10 | 확정 카운트 |
| **stale_threshold** | 90 | 30~300 | ID 삭제 기준 (프레임) |
| **SLOW 임계값** | jam_score **0.30** | 0.0~1.0 | 서행 판정 |
| **CONGESTED 임계값** | jam_score **0.60** | 0.0~1.0 | 정체 판정 |
| **알림 최소 신뢰도** | 70% | 50~100% | Push 알림 발송 기준 |

> ⚠️ config.py 실제값 기준으로 수정: `learning_frames=1800`, `cos_threshold=-0.75`, `wrong_count_threshold=8`, `smooth_jam_threshold=0.30`, `slow_jam_threshold=0.60`

## 3. 운영 인력 및 역할

### 3.1 조직 구성

| 역할 | 담당자 | 주요 업무 |
|------|--------|-----------|
| **시스템 관리자** | 박대원 | 파이프라인 코드 유지보수, 버그 수정, 모델 업데이트, 파라미터 조정 |
| **QA / 기획 담당** | 이수빈 | 산출물 관리, 화면 설계, 요구사항 검증, 탐지 정확도 QA |
| **현장 운영자** | 교통관리센터 요원 | 이벤트 정탐/오탐 판단, 대응 조치 요청, 이상 상황 보고 |

### 3.2 운영자 업무 흐름

현장 운영자는 아래 절차에 따라 이벤트를 처리한다.

| 단계 | 화면 | 수행 내용 |
|------|------|-----------|
| **Step 1** | SCR-01 메인 대시보드 | 시스템 접속 후 전체 현황 확인. KPI 카드 4종 및 CCTV 그리드 모니터링. |
| **Step 2** | SCR-02 이벤트 알림 팝업 | 자동 감지 알림 수신 시 팝업 확인. CCTV 미리보기로 현장 영상 확인. |
| **Step 3** | SCR-03 CCTV 상세 뷰 | [CCTV 상세 보기] 클릭 시 풀스크린 영상 및 오버레이 정보 분석. |
| **Step 4** | SCR-02 판단 | [정탐 확인] 또는 [오탐 처리] 선택. 오탐 시 사유 선택 필수. |
| **Step 5** | SCR-04 해결 방안 | 정체 정탐 확인 후 4단계 대응 절차(VSL→VMS→램프→순찰) 순서 진행. |
| **Step 6** | SCR-05 이벤트 로그 | 처리 이력 확인 및 미처리 이벤트 재검토. 필요 시 CSV 내보내기. |

### 3.3 근무 체계

| 구분 | 내용 | 비고 |
|------|------|------|
| **운영 시간** | 24시간 / 365일 상시 운영 | 3교대 (08:00~16:00 / 16:00~24:00 / 00:00~08:00) |
| **이벤트 응답 목표** | 역주행: 즉시 (알림 후 30초 이내) | 정체: 3분 이내 정탐/오탐 판단 |
| **모바일 알림** | 허용 운영자에게 Push 알림 발송 | 신뢰도 70% 이상 이벤트만 발송 |
| **미처리 이벤트 기준** | 30분 이상 미처리 시 상위 보고 | SCR-09 업무현황 화면에서 확인 |

## 4. 성능 KPI 및 모니터링 기준

### 4.1 핵심 성과 지표 (KPI)

본 시스템의 목표 정확도는 한국도로공사 기준 90% 이상이며, 다음 지표를 기준으로 성과를 측정한다.

| 지표 | 목표치 | 경고 기준 | 측정 방법 |
|------|--------|---------|-----------|
| **탐지 정확도 (전체)** | **≥ 90%** | **< 85%** | 정탐 / (정탐+오탐+미탐) × 100 |
| **역주행 정탐률** | **≥ 92%** | **< 88%** | events_log.csv 정탐 기록 분석 |
| **정체 탐지 정확도** | **≥ 90%** | **< 85%** | frame_log.csv congestion_level 비교 |
| **평균 이벤트 응답시간** | **< 1분 30초** | **> 3분** | SCR-09 평균 응답시간 집계 |
| **오탐률** | **≤ 10%** | **> 15%** | 이벤트 로그 오탐 사유 집계 |
| **예측 적중률 (SCR-08)** | **≥ 80%** | **< 70%** | 선제 대응 후 실제 정체 발생 여부 |
| **시스템 가동률** | **≥ 99.5%** | **< 99%** | 월간 다운타임 / 총 운영시간 |

### 4.2 정체 레벨 판정 기준

| 레벨 | 속도 기준 | 대응 방안 | 배지 색상 |
|------|---------|-----------|---------|
| **SMOOTH** | jam_score < **0.30** | 정상 모니터링 유지 | 초록 (#22C55E) |
| **SLOW** | **0.30** ≤ jam_score < **0.60** | 모니터링 강화 + 예측 배너 활성 | 노랑 (#EAB308) |
| **CONGESTED** | jam_score ≥ **0.60** | 4단계 해결 절차 즉시 진행 | 빨강 (#EF4444) |

### 4.3 KPI 모니터링 주기

| 모니터링 항목 | 주기 | 확인 방법 |
|-------------|------|-----------|
| **실시간 KPI 4종** | 1초 | SCR-01 메인 대시보드 KPI 카드 |
| **탐지 신뢰도 게이지** | 5초 | SCR-01 정확도 반원 게이지 |
| **이벤트 피드** | 실시간 | SCR-01 이벤트 피드 (최근 20건) |
| **일일 정탐/오탐률** | 24시간 | SCR-06 통계 리포트 |
| **운영자 응답시간** | 교대 시마다 | SCR-09 운영자 업무 현황 |
| **예측 적중률** | 7일 | SCR-08 예측 정확도 추이 차트 |
| **시스템 가동률** | 월간 | 로그 파일 분석 + 장애 이력 |

| **Step 6** | P1 미해결 시 즉시 박대원 에스컬레이션 + 수동 순찰 요청 |

#### 5.2.2 오탐 급증 (P2)

| 순서 | 조치 내용 |
|------|-----------|
| **Step 1** | 오탐 사유 패턴 분석 — 사유별 집계 (SCR-05 이벤트 로그 CSV 내보내기) |
| **Step 2** | 가장 많은 오탐 사유가 '카메라 앵글 문제'이면 cos_threshold 값 조정 (-0.75 → -0.8) |
| **Step 3** | IC/JC 구간 오탐 급증 시 해당 구역 그리드 셀의 Flow Map 수동 보정 검토 |

| **Step 5** | 개선 후 24시간 오탐률 재측정 — 목표(10% 이하) 미달 시 재학습(flow_map 초기화 후 재실행) |
