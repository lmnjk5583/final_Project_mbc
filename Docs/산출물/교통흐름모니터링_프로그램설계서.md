## 1. 시스템 개요

### 1.1 프로젝트 배경 및 목적

서울은 TomTom 2026 기준 세계 상위권 혼잡 도시로, 교통 혼잡 경제 손실은 연간 70조 원(서울만 30조 원)에 달한다. 고속도로 상습 정체 구간 429.9km(2024), 주말 정체 4~6시간 지속, 국토부 2026년 정체 30% 감축 목표가 본 프로젝트의 배경이다.

v1.0에서 완성된 역주행 탐지 시스템을 기반으로, v2.0에서는 교통 정체 감지 신기능(jam_score·SMOOTH/SLOW/CONGESTED)과 풀스택 통합(Flask + WebSocket + React 대시보드)을 추가한다.

### 1.2 시스템 범위

| 구분 | 내용 |
|------|------|
| ✅ 포함 | 역주행 탐지 고도화 / jam_score 기반 정체 감지 / 방향별(A/B) 분리 탐지 / 정체 이벤트 DB 저장 / 관제 대시보드 WebSocket 연동 / YOLO11n 추가학습 |
| ❌ 제외 | 웹 UI·Flask 라우트(팀원 담당) / 탄소배출 기능 / 역주행 핵심 로직 수정 / 절대 km/h 측정(ITS API 미제공) |

### 1.3 핵심 설계 원칙

| 원칙 | 설명 |
|------|------|
| 비율 기반 지표 | 모든 정체 지표를 학습 구간 baseline 대비 상대 비율로 계산 → 화각·줌 변경 후에도 자동 보정 |
| footpoint 기준 | 차량 위치를 bbox 하단 중심(fy=y2)으로 통일 → 원근 왜곡 최소화, 셀 배정·passage·feature 일관성 |
| 방향별 분리 탐지 | flow_map 기준 방향 벡터로 A방향(코사인≥0)/B방향(코사인<0) 분류 → 각 방향 독립 jam_score 판정 |
| 역주행 로직 불변 | judge.py 핵심 알고리즘 수정 금지. 신규 기능은 별도 모듈로 추가. 기존 테스트 케이스 PASS 유지 |
| TDD 방법론 | 새 모듈 구현 전 테스트 케이스 먼저 작성 → pytest PASS 후 다음 단계 진행 |
| 단계적 개발 | Phase 1(규칙 기반 jam_score) → Phase 2(GRU 40% 혼합) → Phase 3(GRU 65%) |

## 2. 시스템 아키텍처

### 2.1 전체 4계층 구성

| 계층 | 구성 요소 |
|------|-----------|
| **입력층** | CCTV 영상 → run_wrongway.py (진입점 / 설정 조립) |
| **AI 코어** | config.py / state.py / tracker.py (YOLO11n+ByteTrack) / detector.py (오케스트레이터) / visualizer.py / flow_map.py (20×20 Grid EMA) / judge.py (코사인유사도+투표) / id_manager.py (3중 게이트 재매칭) / camera_switch.py / bbox_stabilizer.py |
| **신규 모듈** | baseline_stats.py / passage_tracker.py / feature_extractor.py / congestion_judge.py / traffic_analyzer.py (래퍼·CongestionPredictor) / gru_module.py (Phase 2) |
| **백엔드·프론트** | Flask (REST API) → WebSocket (/ws/traffic 1초, /ws/alerts 즉시) → React Dashboard (CCTV 그리드 뷰, 실시간 지표 차트, 팝업 알림, 이벤트 로그) |

### 2.2 데이터 흐름

```
① CCTV 프레임 → YOLO11n+ByteTrack → 차량 트랙 목록 생성

② [학습 모드] 정상 차량 이동 벡터 → FlowMap EMA 누적
            + PassageTracker(메인) 진입·퇴장 기록 → BaselineStats 산출

③ [학습 완료] apply_spatial_smoothing() + apply_boundary_erosion()
            → finalize_baseline()
            → A/B 방향별 TrafficAnalyzer에 baseline 복사 주입
            → flow_map.npy(version 2) 저장

④ [탐지 모드] _classify_direction()으로 차량별 A/B 분류
            → 방향별 FeatureExtractor → 7차원 feature 벡터
            → CongestionJudge → jam_score + 레벨 판정
            → visualizer + CSV 로그 + WebSocket 이벤트
```

### 2.3 저장 파일 목록

| 파일 | 경로 | 설명 |

| events_log.csv | logs/run_YYYYMMDD/ | 역주행·정체 이벤트 로그 |

### 3.2 신규 모듈

#### 3.2.1 baseline_stats.py — 데이터 클래스

| 클래스 | 주요 필드 |
|--------|-----------|
| **PassageRecord** | track_id, entry_frame, entry_fx/fy, exit_frame, exit_fx/fy, dwell_frames, entry_exit_dist, is_complete │ property is_valid: is_complete AND dwell>0 AND dist≥min_passage_dist |
| **BaselineStats** | free_flow_dwell, typical_dwell, norm_speed_ref, count_ref, bbox_slope, bbox_intercept, lcs(0~1), quality_warning, passage_count, is_fallback |

#### 3.2.2 passage_tracker.py — 3-Tracker 구조

Detector는 PassageTracker를 3개 인스턴스로 운용한다.

| 인스턴스 | 역할 |
|----------|------|
| **passage_tracker (메인)** | 학습·재학습 모드 전담. on_entry/on_exit 수신, record_frame_stats 누적, finalize_baseline() 호출. 탐지 모드에서는 사용 안 함 |
| **passage_tracker_a** | 탐지 모드 전담 — A방향(코사인≥lane_cos_threshold) 차량 record_frame_stats 수집. TrafficAnalyzer_a의 FeatureExtractor에 주입 |
| **passage_tracker_b** | 탐지 모드 전담 — B방향 차량 record_frame_stats 수집. TrafficAnalyzer_b의 FeatureExtractor에 주입 |

`on_entry`: Detector.run() 메인 루프에서 first_seen_frame 등록 시 직접 호출 (메인 PT 전용).

`on_exit`: Detector.run() 메인 루프에서 gone_ids 처리 시 직접 호출. footpoint 있으면 is_complete=True, 없으면 False.

| 메서드 | 설명 |
|--------|------|
| on_entry(tid,fx,fy,frame_num) | 진입 위치·프레임 캐시 + state.entry_positions 기록 |
| on_exit(tid,fx,fy,frame_num,is_complete) | PassageRecord 생성 후 _passages 리스트에 추가 |
| record_frame_stats(active,exit,norms,cy,bh) | 매 프레임 활성 수·퇴장 수·norm_mags·cy·bbox_h 누적 |
| get_completed_count() | is_valid=True인 passage 수 반환 |
| finalize_baseline() | 학습 완료 시 1회 호출. BaselineStats 산출 반환 |
| compute_lcs() | §4.3 수식으로 LCS 계산 (코드 실측 기준) |
| get_current_dwells(active_ids,frame_num) | 현재 활성 차량들의 체류 프레임 수 리스트 |
| get_exit_count_recent(n_frames) | 최근 n_frames 동안 퇴장 차량 수 합계 |
| update_baseline(fx,fy,norm_mag) | SMOOTH 온라인 구간 norm_speed_ref EMA 점진 갱신 (alpha=0.01) |
| reset() | 카메라 전환 시 전체 초기화 |

#### 3.2.3 feature_extractor.py — 7차원 feature 벡터

baseline이 설정되지 않으면 None 반환. 모든 값이 baseline 대비 비율이므로 화각 변경 후에도 의미 유지.

| idx | 이름 | 실제 코드 계산식 | 범위 | 비고 |
|-----|------|-----------------|------|------|
| 0 | **norm_speed_ratio** | median(upper_50%_of_norm_mags) / max(norm_speed_ref,0.01) | 0~1 | 상위 50% 중앙값 |
| 1 | **count_ratio** | active_count / max(count_ref,1) | 0~3 | clip(0,3) |
| 2 | **stop_ratio** | stopped_count / max(speed_known_count,1) | 0~1 | 분모=speed_known_count (신규 차량 제외) |
| 2.5 | **slow_ratio** | slow_count / max(speed_known_count,1) | 0~1 | 0.06 ≤ nm < 0.15 차량 비율 |
| 3 | **exit_rate_ratio** | exit_last_N / max(count_ref×0.5,0.01) | 0~3 | clip(0,3). N=exit_rate_window |
| 4 | **dwell_ratio** | free_flow_dwell / max(mean(current_dwells),1) | 0~1 | clip(0,1). 1.0=정상 |
| 5 | **density_score** | clip(raw_density / (density_max_vehicles/grid²), 0, 1) | 0~1 | 포화기준=40대. |
| 6 | **rule_jam_score** | CongestionJudge.compute_jam()이 역주입 | 0~1 | Phase 2 GRU 보조 입력 |

`speed_known_count`: 궤적이 velocity_window 이상 쌓인 차량(speeds 딕셔너리에 등록된 차량). 신규 등장 차량은 분모·분자 모두 제외.

`density_score` 정규화: raw_density(=occupied_cells/total_cells) ÷ (density_max_vehicles÷grid_size²) 로 현실적 포화 기준 적용. 40대 이상이면 1.0(포화).

#### 3.2.4 congestion_judge.py — jam_score + 레벨 판정

| 메서드 | 설명 |
|--------|------|
| compute_jam_score(x_t,lcs,cfg) | 정상 모드: 0.55×speed_score + 0.35×stop_score + 0.10×(speed×stop) - bonus. bonus=유출원활(+0.06)+비정지(+0.06)+원활주행(+0.08) |
| compute_jam_score_fallback(x_t) | fallback: 0.50×slow_ratio + 0.30×stop_ratio + 0.20×density_score |
| set_baseline(baseline) | BaselineStats 주입. EMA 초기값 0.5 설정(중립 수렴 전략) |
| compute_jam(x_t) | rule_jam 계산 후 x_t['rule_jam_score']에 역주입 (Phase 2 분리 호출 지원) |
| apply_level(jam,frame_num) | 비대칭 EMA(악화 alpha_up=0.10, 호전 alpha_down=0.04) → LCS 보정 임계값으로 레벨 분류 → 히스테리시스 → 정체 지속 시간 추적 |
| update(x_t,frame_num) | compute_jam() + apply_level() 통합. (level: str, ema_jam: float) 반환 |
| reset() | 카메라 전환 시 EMA·히스테리시스·정체 시작 프레임 초기화 (baseline 유지) |

#### 3.2.5 CongestionPredictor (traffic_analyzer.py 내)

방향별 predictor_a / predictor_b 인스턴스로 운용. 탐지 모드에서 매 프레임 traffic_analyzer.get_avg_speed()를 입력받아 단기 정체 예측 수행.

| 속성 | 내용 |
|------|------|
| **prediction_history_window** | 속도 히스토리 창 = 30프레임 (config.prediction_history_window) |
| **prediction_horizon** | 예측 시간 범위 = 5분 (config.prediction_horizon) |
| **호출 위치** | detector.py: predictor_a/b.update(traffic_analyzer_a/b.get_avg_speed()) — 탐지 모드 매 프레임 |

#### 3.2.6 gru_module.py (Phase 2)

| 구성 요소 | 내용 |
|-----------|------|
| **신경망 구조** | 입력: T=30프레임×7차원 / GRU 2계층(hidden=64) + FC(64→32 ReLU) → FC(32→3) Softmax → [p_smooth, p_slow, p_congested] |
| **gru_score** | p_slow × 0.5 + p_congested × 1.0 (0~1) |
| **Phase 2 blend** | final_jam = 0.60 × rule_jam + 0.40 × gru_score |
| **Phase 3 blend** | final_jam = 0.35 × rule_jam + 0.65 × gru_score |
| **graceful fallback** | PyTorch 없는 환경에서도 동작 (predict()→None, 학습→no-op) |
| **camera_switch 후** | feature_buffer.clear() + hidden=zeros + warmup_remaining=30 → warmup 중 rule_jam만 사용 |

## 4. 핵심 알고리즘

### 4.1 Grid Flow Map 학습 및 역주행 판별

| 단계 | 알고리즘 | 핵심 파라미터 |
|------|----------|---------------|
| **학습** | 이동 벡터 단위화 → 방향 게이팅(cos<-0.4 차단) → 셀(r,c) EMA 갱신 → 완료 시 apply_spatial_smoothing() + apply_boundary_erosion() | grid_size=20, alpha=0.10, min_samples=5, learning_frames=**1,800** |
| **역주행 판별** | 궤적 샘플링(최대 8포인트) → cos_sim=ndx×flow_vx+ndy×flow_vy → 투표(disagree_ratio≥**0.7**) → count+1 ≥ **8** → 역주행 확정 | cos_threshold=**-0.75**, wrong_count_threshold=**8**, vote_threshold=**0.7** |
| **방향 분류** | _classify_direction(fx,fy): get_interpolated(fx,fy)로 흐름 벡터 조회 → 기준 방향과 코사인 ≥ lane_cos_threshold(0.0)이면 A방향, 미만이면 B방향 | lane_cos_threshold=0.0 |
| **경계 erosion** | 1단계: 4방향 직접 이웃에 cos<-0.5인 셀 발견 시 즉시 제거. 2단계: 3×3 이웃 중 반대방향 비율≥40%이면 제거. eroded_mask로 영구 재학습 금지 | majority_threshold=0.4 |

### 4.2 normalized_mag (원근 보정 속도)

| 수식 | 설명 |
|------|------|
| nm = mag / max(bbox_h, min_bbox_h=30.0) | mag: velocity_window(20)프레임 간 픽셀 이동량. min_bbox_h=30px 클램프: 원거리 소형 박스(bbox_h≈15px)에서 nm 과대 계산 방지 |

> ⚠️ config.py 실제값: `velocity_window=20`, `min_bbox_h=30.0`

### 4.3 LCS (Learning Congestion Score) — 실제 코드 기준

| 신호 | 실제 코드 계산식 | 설명 |
|------|-----------------|------|
| **signal_A** | min((median/max(p10,1)-1)/8, 1.0) | dwell 편중도. p10=percentile(dwells,10). smooth(비율2~3)→0.12~0.25, 정체(4~6)→0.38~0.63 |
| **signal_B** | max(0, 1-mean_speed/max(p95_speed,1e-6)) | 속도 저하. p95=percentile(all_norm_mags,95). bbox 순간 튐 이상치 방지 |
| **signal_C** | min(std(dwells)/median(dwells)/2, 1.0) | dwell 변동계수(CV). smooth=균일분포(CV낮음), 정체=혼재(CV높음). /2 정규화 |
| **LCS** | 0.40×A + 0.35×B + 0.25×C | 유효 passage < 2개면 0.5 반환 |

| LCS 범위 | 판단 | 시스템 동작 |
|----------|------|------------|
| 0.0~0.3 | 정상 학습 | 보정 없이 baseline 사용. 임계값 원본 유지 |
| 0.3~0.6 | 부분 오염 | 경고 출력. smooth_thr·slow_thr 소폭 완화 |
| 0.6~0.8 | 높은 오염 | 경고 출력. smooth_thr·slow_thr 대폭 완화 |
| 0.8~1.0 | 심각 오염 | is_fallback=True → fallback 모드 (density·stop·outflow만으로 판정) |

### 4.4 jam_score 계산 및 레벨 판정

| 구분 | 모드 | 계산식 / 조건 |
|------|------|---------------|
| **정상 모드** | baseline 있음 | 0.55×(1-speed_ratio) + 0.35×stop_ratio + 0.10×(speed_score×stop_score) - bonus |
| **fallback** | LCS≥0.8 또는 baseline 없음 | 0.50×slow_ratio + 0.30×stop_ratio + 0.20×density_score |
| **bonus 항목** | 원활 차감 | exit_rate_ratio>1.3:+0.06 / stop_ratio<0.05:+0.06 / norm_speed_ratio>0.9:+0.08 |
| **비대칭 EMA** | 스무딩 | 악화(jam↑): alpha_up=**0.10** / 호전(jam↓): alpha_down=**0.04** |
| **LCS 보정** | 임계값 조정 | smooth_thr=**0.30**×(1-lcs×0.40) / slow_thr=**0.60**×(1-lcs×0.30) |

| 레벨 | 조건 (EMA jam 기준) | 시각화 | 조치 권고 |
|------|---------------------|--------|-----------|
| **SMOOTH** | jam < smooth_thr | 초록 배지 | — |
| **SLOW** | smooth_thr ≤ jam < slow_thr | 노랑 배지 | VSL 하향 / VMS 서행 안내 |
| **CONGESTED** | jam ≥ slow_thr | 빨강 배지 | VMS 우회 / 램프 미터링 / 5분+ 시 순찰대 |

히스테리시스: congestion_hysteresis_sec(=**3.0**) × fps 프레임 동안 기존 레벨 유지 후 전환.

### 9.2 baseline freeze 조건 (탐지 모드 온라인 학습)

초기 학습 중에는 무조건 학습. 탐지 모드(enable_online_flow_update=True)에서만 아래 5가지 조건 모두 충족 시 baseline 갱신.

| 조건 | 이유 |
|------|------|
| cfg.enable_online_flow_update == True | 온라인 갱신 설정 활성화 |
| is_wrong == False | 역주행 의심 차량 제외 |
| st.wrong_way_count[tid] == 0 | 한 번이라도 의심된 차량 제외 |
| congestion_level == 'SMOOTH' | 정체 중 baseline 오염 방지 |
| len(active_ids) >= min_active_for_baseline | 최소 2대 이상 있어야 통계 의미 있음 |

### 9.3 학습 연장 조건

learning_frames(1,800) 도달 시 min_passages_required(5) 미달이면 max_learning_frames(=1,800×1.5=2,700프레임)까지 연장. max_learning_frames 도달 시 passage 수와 무관하게 강제 종료.

재학습도 동일 로직: relearn_frames(300) + 최대 relearn_frames×1.5(=450).
