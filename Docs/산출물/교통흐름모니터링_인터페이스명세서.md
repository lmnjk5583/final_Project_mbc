## 1. 문서 개요

본 명세서는 교통 이상징후 탐지 시스템 v2.0의 모든 인터페이스(입력/출력, 내부 모듈 간 인터페이스, 외부 시스템 연동 인터페이스)를 정의한다. 기획서·요구사항정의서·화면설계서·유스케이스·업무흐름도·dev_guide.md를 종합하여 작성하였다.

> **【타입 표기 규칙】**
> 본 명세서의 타입 표기는 가독성 우선의 명세서 표기법을 따르며 Python 코드 문법과 무관하다. 'A | B'는 'A 또는 B', 'list[X]'는 'X의 리스트'를 의미한다. 실제 구현체(Python 3.9+)에서는 Optional[X] 또는 Union[A, B] 형태를 사용한다.

### 1.1 시스템 구조 개요

전체 시스템은 AI 코어 레이어, 신규 정체 탐지 모듈 레이어, 백엔드/프론트 레이어로 구분된다.

| 레이어 | 구성 모듈 | 역할 |
|--------|-----------|------|
| AI 코어 | config.py, state.py, tracker.py, judge.py, id_manager.py, flow_map.py, camera_switch.py, bbox_stabilizer.py, detector.py, visualizer.py, logger.py | 역주행 탐지 핵심 처리 (완료 — 수정 금지 원칙 적용) |
| 신규 정체 모듈 | baseline_stats.py, passage_tracker.py, feature_extractor.py, congestion_judge.py, traffic_analyzer.py | 교통 정체 탐지 (Phase 1 개발 대상) |
| 백엔드·프론트 | Flask REST API, WebSocket, MySQL, React 대시보드 | 외부 시스템 연동 (Phase 3 — 팀원 담당) |

## 4. 내부 모듈 인터페이스

### 4.1 TrafficAnalyzer (traffic_analyzer.py)

정체 탐지 래퍼 클래스. 기존 인터페이스 시그니처 및 반환 타입을 유지하면서 내부를 FeatureExtractor + CongestionJudge 조합으로 교체.

#### 4.1.1 생성자

| 파라미터 | 타입 | 설명 |
|----------|------|------|
| cfg | DetectorConfig | 전체 파라미터 설정 객체 |
| frame_w / frame_h | int | 프레임 너비·높이 (픽셀) |
| fps | float | 영상 FPS |
| flow_map | FlowMap │ None | FlowMap 참조 (Phase 2 확장용) |
| passage_tracker | PassageTracker │ None | 진입·퇴장 기록 모듈 |
| congestion_judge | CongestionJudge │ None | 외부 주입 가능, None이면 내부 생성 |
| gru_module | GRUModule │ None | Phase 2 GRU, None이면 Phase 1 모드 |

#### 4.1.2 공개 메서드

| 메서드 시그니처 | 반환 타입 | 설명 |
|----------------|-----------|------|
| set_state(state) | None | DetectorState 주입 → FeatureExtractor 초기화 (detector.py에서 호출) |
| set_baseline(baseline) | None | 학습 완료 후 BaselineStats를 FE·CJ에 전달 |
| update(tracks, speeds, frame_num) | None | 매 프레임 호출. tracks: list[dict], speeds: {id:mag} |
| get_congestion_level() | str | "SMOOTH" / "SLOW" / "CONGESTED" |
| get_jam_score() | float 0~1 | 현재 jam_score |
| get_density_map() | np.ndarray (20×20) | 셀별 차량 밀도 (복사본 반환) |
| get_avg_speed() | float | norm_speed_ratio × 100 (정상 대비 %, 절대 km/h 아님) |
| get_occupancy() | float | 점유율 % (차량 있는 셀 수 / 전체 셀) |
| get_volume() | float | 교통량 대/시 (픽셀 기반 근사) |
| get_duration_sec() | float | SLOW/CONGESTED 지속 시간(초), SMOOTH이면 0.0 |
| get_affected_vehicles() | int | mag < stop_mag_threshold 미만 차량 수 |
| get_last_feature() | dict │ None | 마지막 update의 feature 벡터 (GRU online_step용) |

### 4.2 PassageTracker (passage_tracker.py)

차량의 화면 진입·퇴장을 추적하여 PassageRecord를 생성하고 BaselineStats를 산출한다.

| 메서드 시그니처 | 반환 타입 | 설명 |
|----------------|-----------|------|
| on_entry(track_id, fx, fy, frame_num) | None | 첫 등장 시 호출 — state.entry_positions 기록 |
| on_exit(track_id, fx, fy, frame_num, is_complete) | None | 퇴장 시 호출 — PassageRecord 생성 |
| record_frame_stats(active_count, exit_count, norm_mags, cy_vals, bbox_h_vals) | None | 매 프레임 통계 누적 |
| get_completed_count() | int | 유효 완성 passage 수 반환 |
| finalize_baseline() | BaselineStats | 학습 완료 시 호출 — 기준선 통계 산출 |
| compute_lcs() | float | 현재 데이터 기준 LCS(0~1) 계산 |
| update_baseline(fx, fy, norm_mag) | None | SMOOTH 온라인 구간에서 baseline 점진 갱신 |
| get_current_dwells(active_ids, frame_num) | list[int] | 현재 활성 차량들의 체류 프레임 수 리스트 |
| reset() | None | 카메라 전환 시 전체 초기화 |

### 4.3 FeatureExtractor (feature_extractor.py)

7차원 feature 벡터를 계산한다. 모든 값은 baseline 대비 비율로 정규화 (화각 변경 시에도 의미 불변).

| idx | 이름 | 계산식 | 범위 | 비고 |
|-----|------|--------|------|------|
| 0 | norm_speed_ratio | mean(norm_mags) / max(norm_speed_ref, 0.01) | 0~1 | clip(0,1) |
| 1 | count_ratio | active_count / max(count_ref, 1) | 0~∞ | clip(0,3) |
| 2 | stop_ratio | stopped_count / max(speed_known_count, 1) | 0~1 | mag/bbox_h < **0.06** |
| 2.5 | slow_ratio | slow_count / max(speed_known_count, 1) | 0~1 | 0.06 ≤ nm < 0.15 차량 비율 |
| 3 | exit_rate_ratio | exit_last_30f / max(count_ref×0.5, 0.01) | 0~∞ | clip(0,3) |
| 4 | dwell_ratio | free_flow_dwell / max(mean(current_dwells), 1) | 0~1 | clip(0,1) |
| 5 | density_score | clip(raw_density / (density_max_vehicles/grid²), 0, 1) | 0~1 | 기존 밀도맵 활용 |
| 6 | rule_jam_score | CongestionJudge.compute_jam() 역주입 | 0~1 | Phase 2 GRU 보조 입력 |

### 4.4 CongestionJudge (congestion_judge.py)

jam_score 계산, 레벨 판정, 비대칭 EMA 스무딩, 히스테리시스를 담당한다.

| apply_level(final_jam, frame_num) | (str, float) | EMA 스무딩 + 히스테리시스 적용 후 (레벨, 점수) 반환 |

#### 4.4.1 jam_score 계산 공식 (Phase 1 — baseline 있음)

| 구성 요소 | 가중치 | 계산식 |
|-----------|--------|--------|
| speed_score | 0.55 | clip(1 − norm_speed_ratio, 0, 1) |
| stop_score | 0.35 | clip(stop_ratio, 0, 1) |
| congestion_synergy (복합 정체) | 0.10 | speed_score × stop_score |
| improvement bonus (차감) | – | exit_rate_ratio > 1.3 → −0.06 / stop_ratio < 0.05 → −0.06 / norm_speed_ratio > 0.9 → −0.08 |

#### 4.4.2 레벨 판정 임계값 (LCS 보정 포함) — config.py 실제값 기준

| 레벨 | 판정 조건 | 배지 색상 | 비고 |
|------|-----------|-----------|------|
| **SMOOTH** | jam_score < **0.30** × (1 − LCS×0.40) | 초록 (#22C55E) | 최저 임계값 0.15 |
| **SLOW** | **0.30** ≤ jam_score < **0.60** × (1 − LCS×0.30) | 노랑 (#EAB308) | 최저 임계값 0.38 |
| **CONGESTED** | jam_score ≥ **0.60** × (1 − LCS×0.30) | 빨강 (#EF4444) | 히스테리시스 **3.0**초 유지 후 해제 |

## 5. 데이터 구조 (baseline_stats.py)

### 5.1 PassageRecord

개별 차량의 화면 진입→퇴장 기록을 담는 데이터 클래스.

| 필드 | 타입 | 설명 |
|------|------|------|
| track_id | int | ByteTrack ID |
| entry_frame | int | 화면 진입 프레임 번호 |
| entry_fx / entry_fy | float | 진입 시 footpoint 좌표 (fx=(x1+x2)/2, fy=y2) |
| exit_frame | int | 화면 퇴장 프레임 번호 |
| exit_fx / exit_fy | float | 퇴장 시 footpoint 좌표 |
| dwell_frames | int | 체류 프레임 수 (exit_frame − entry_frame) |
| entry_exit_dist | float | 진입~퇴장 직선 거리 (픽셀) |
| is_complete | bool | True=정상 퇴장, False=stale 강제 종료 |
| is_valid (property) | bool | is_complete AND dwell_frames>0 AND dist≥min_passage_dist |

### 5.2 BaselineStats

학습 구간 종료 시 산출되는 기준선 통계. 정체 판정의 모든 비교 기준이 이 객체에 담긴다.

| 필드 | 타입 | 설명 |
|------|------|------|
| free_flow_dwell | float | 자유 흐름 체류 시간: n≥10이면 percentile(10), n<10이면 min |
| typical_dwell | float | 일반 체류 시간: median(dwells) |
| norm_speed_ref | float | 학습 구간 전체 normalized_mag의 중앙값 |
| count_ref | float | 학습 구간 프레임당 평균 활성 차량 수 |
| bbox_slope / bbox_intercept | float | bbox_h ~ cy 선형회귀 기울기·절편 (원근 보정용) |
| lcs | float | Learning Congestion Score (0.0~1.0). 학습 품질 지표 |
| quality_warning | bool | True이면 typical_dwell > free_flow_dwell × 3 (정체 중 학습 의심) |
| passage_count | int | 기준 산출에 사용된 유효 passage 수 |
| is_fallback | bool | True=passage 부족 → fallback 모드 (밀도·정지율 기반 판정) |

### 5.3 LCS (Learning Congestion Score) 계산

학습 구간이 얼마나 정체 상태였는지를 0~1로 점수화. 임계값 보정에 사용.

| LCS 범위 | 판단 | 시스템 동작 |
|----------|------|------------|
| 0.0~0.3 | 정상 학습 | 보정 없이 baseline 사용 |
| 0.3~0.6 | 부분 오염 | 경고 출력, threshold 소폭 완화 |
| 0.6~0.8 | 높은 오염 | 경고 출력, threshold 대폭 완화 |
| **0.8~1.0** | **심각 오염** | **is_fallback=True → fallback 모드 강제 전환** |
