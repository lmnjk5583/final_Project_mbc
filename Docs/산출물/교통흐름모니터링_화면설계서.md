# 교통흐름 모니터링 화면설계서
**Traffic Flow Monitoring — Screen Design Specification v1.1**
※ 고속도로 CCTV 이상징후 탐지 시스템 중 교통흐름 모니터링 파트 화면 설계

| 항목 | 내용 |
|------|------|
| 문서 버전 | v1.1 |
| 작성일 | 2026-04-02 |
| 작성자 | 이수빈 |
| 목표 정확도 | 90% 이상 (한국도로공사 기준) |
| 참고 논문 | Kumar & Raubal, TRC Vol.133, 2021 |

---

## 1. 개정 이력

| 버전 | 작성일 | 작성자 | 변경 내용 |
|------|--------|--------|-----------|
| v1.0 | 2026-03-25 | 이수빈 | 초안 작성 (9개 화면) |
| v1.1 | 2026-04-02 | 이수빈 | 절대 km/h → 정상 대비 속도(%) 전환 (ITS API 미제공으로 절대 속도 측정 불가 확정). LSTM → GRU 수정. 정체 판정 기준 jam_score 기반으로 변경. |

---

## 2. 시스템 개요

| 항목 | 내용 |
|------|------|
| 시스템명 | 고속도로 CCTV 영상 기반 이상징후 탐지 시스템 |
| 주요 기능 | ① 역주행 차량 탐지  ② 교통 정체 모니터링 |
| 파이프라인 | YOLO11n(감지) → ByteTrack(추적) → Flow Map(방향학습) → Judge(판정) → Logger |
| 목표 정확도 | 속도·교통량·점유율 90% 이상 (한국도로공사 기준) |
| 동작 모드 | LEARNING(학습) → DETECTING(탐지) → RELEARNING(재학습) |

## SCR-01 메인 대시보드

| 항목 | 내용 |
|------|------|
| **화면 ID** | SCR-01 |
| **화면명** | 메인 대시보드 |
| **목적** | 전체 도로 현황을 한눈에 파악, 이벤트 발생 시 즉시 인지 |
| **트리거/접근** | 로그인 후 기본 화면 / 상단 탭 '대시보드' |

### 화면 미리보기

```
┌─────────────────────────────────────────────────────────────────────┐
│ 로고  교통흐름 모니터링          2026-03-25 14:23 / 날씨 / 알림 3건  │
├────────────────────┬────────────────────────────────────────────────┤
│ 사이드바            │ CAM-01 [SMOOTH] │ CAM-02 [SLOW] │ CAM-03 [SMOOTH]│
│ 모드 배지 DETECTING │                                                │
│ KPI 카드 4종        │ CAM-04 [SMOOTH] │ CAM-05 [CONGESTED]│CAM-06[SMOOTH]│
│ 속도 / 밀도         │                                                │
│ 교통량 / 점유율     │      예측: 15분 후 2구간 정체 예상 (78%)        │
│ 정확도 게이지(90%)  ├────────────────────────────────────────────────┤
│ 알림 카운터         │ 최근 이벤트                                     │
│ 역주행 2건          │ 14:23 역주행 CAM-07 [확인]                      │
│ 정체 5건            │ 14:21 정체 CAM-05 [확인]                        │
│                    │ 14:18 정체 CAM-12 [확인]                        │
├────────────────────┴────────────────────────────────────────────────┤
│ [대시보드] [CCTV상세] [이벤트로그] [통계] [예측] [업무현황] [설정]    │
└─────────────────────────────────────────────────────────────────────┘
```

### 화면 구성요소

| No | 구성요소 | 설명 | 비고 |
|----|----------|------|------|
| 1 | 상단 바 | 시스템 로고, 현재 날짜/시간, 날씨, 알림 벨(미확인 수) | 고정 헤더 |
| 2 | 동작 모드 배지 | LEARNING(파랑) / DETECTING(초록) / RELEARNING(주황) | 실시간 갱신 |
| 3 | KPI 카드 4종 | 정상 대비 속도(%), 차량밀도(대/km), 교통량(대/시), 점유율(%) | 1초 주기 |
| 4 | 정확도 게이지 | 현재 탐지 신뢰도 반원 게이지, 목표선 90% | 5초 주기 |
| 5 | CCTV 그리드 | 2×3 / 3×3 전환, 썸네일에 카메라ID + 정체레벨 배지 | 클릭→SCR-03 |
| 6 | 이벤트 카메라 강조 | 이벤트 발생 카메라 썸네일 빨간 테두리 깜빡임(1Hz) | CSS 애니메이션 |
| 7 | 예측 배너 | '15분 후 N구간 정체 예상(N%)' — GRU 예측 결과 | 클릭→SCR-08 |
| 8 | 히트맵 토글 | 도로 구간별 혼잡도 색상 오버레이 ON/OFF | TOPIS 참고 |
| 9 | 이벤트 피드 | 최근 이벤트 20건 시간역순 스크롤, 유형별 색상 구분 | 실시간 |

### 이벤트 정의

| 이벤트/입력 | 동작/출력 | 이동 화면 |
|-------------|-----------|-----------|
| CCTV 썸네일 클릭 | 해당 카메라 풀스크린 뷰 표시 | → SCR-03 |
| 이벤트 피드 [확인] 클릭 | 해당 이벤트 알림 팝업 표시 | → SCR-02 |
| 예측 배너 클릭 | 예측 대시보드로 이동 | → SCR-08 |
| 알림 벨 클릭 | 미확인 이벤트 목록 드롭다운 표시 | - |
| 이벤트 자동 감지 | 피드에 추가 + 경보음 + 카메라 깜빡임 | → SCR-02 (자동) |

| 항목 | 내용 |

```

│ 역주행 감지  /  정체 감지                      │  X 닫기  │

│ 카메라: CAM-07 (부산방향 32.4km)  감지 시각: 14:23:07    │
│ 차량 ID: W1  │  신뢰도: 87.3%  │  지속 시간: 00:00:12   │
├──────────────────────────────────────────────────────────┤
│                                                          │
│         CCTV 미리보기 썸네일                              │
│         (감지 차량에 빨간 바운딩 박스 표시)               │
│                                                          │
├──────────────────────────────────────────────────────────┤
│                    [CCTV 상세 보기]                       │
├──────────────────────────────────────────────────────────┤
│                     운영자 판단                           │
```

### 화면 구성요소

| No | 구성요소 | 설명 | 비고 |
|----|----------|------|------|
| 1 | 헤더 영역 | 이벤트 유형 표시 — 역주행(빨강) / 정체SLOW(주황) / 정체CONGESTED(진빨강) | 색상 코드 구분 |
| 2 | 이벤트 정보 | 카메라 ID, 위치, 감지 시각, 차량 ID, 신뢰도(%), 지속 시간 | - |
| 3 | CCTV 미리보기 | 해당 카메라의 실시간 스냅샷, 감지 차량에 빨간 BBox 표시 | 썸네일 크기 |
| 4 | [CCTV 상세 보기] | SCR-03으로 이동하여 풀스크린 영상 확인 | 새 탭/팝업 |
| 5 | [정탐 확인] | 이벤트를 정탐(True Positive)으로 기록 | 아래 상세 |
| 6 | [오탐 처리] | 오탐 사유 드롭다운 표시 → 제출 시 오탐으로 기록 | 아래 상세 |

### 버튼 동작 상세

| 버튼 | 조건 | 동작 |
|------|------|------|
| [정탐 확인] | 역주행 이벤트 | 경보음 발생 + 화면 상단 빨간 배너 지속 표시 + 로그에 정탐 기록 |
| [정탐 확인] | 정체 이벤트 | SCR-04 (정체 해결 방안) 우측 드로어 슬라이드인 + 로그에 정탐 기록 |
| [오탐 처리] | 클릭 시 | 오탐 사유 드롭다운 표시 |
| [오탐 처리] | 사유 제출 후 | 이벤트 로그에 오탐+사유 기록, 팝업 닫힘, 모델 재학습 피드백 수집 |

### 오탐 사유 목록

**역주행 이벤트 오탐 사유**

| No | 사유 | 설명 |

| 2 | 합류·분기 구간 오인식 | IC/JC 구간에서 진출입 차량을 역주행으로 오탐 |
| 3 | 저속 정상 주행 | 공사 구간 등 저속 주행 차량을 역주행으로 오인 |
| 4 | 그림자·반사광 | 조명 조건에 의해 이동 벡터 오산출 |
| 5 | 기타 | 직접 입력 (텍스트 필드) |

**정체 이벤트 오탐 사유**

| No | 사유 | 설명 |
|----|------|------|
| 1 | 자유속도 기준 미설정 | 해당 구간 자유속도가 미보정되어 임계값 오적용 |
| 2 | 저속 정상 구간 | 공사/진출입 구간 등 원래 저속 구간을 정체로 오인 |
| 3 | 일시적 속도 감소 | 신호 대기 등 일시 서행을 정체로 판정 |
| 4 | 기타 | 직접 입력 (텍스트 필드) |

### 4단계 해결 절차 상세

| 단계 | 전략 | 동작 | 기대 효과 | 근거 |
|------|------|------|-----------|------|
| Step 1 | 가변 속도 제한 (VSL) | 상류부 2~3km 구간 속도 단계적 하향 (100→80→60) | 충돌위험 5~17%↓ 통행시간 10~25%↓ | Kumar(2021) DRL 최적 속도 |

| Step 3 | 램프 미터링 | 인근 IC 진입 간격 확대 (30초→45초), 다중 램프 균형 제어 | 속도 4~13%↑ 사고 21%↓ | Puget Sound 20년 운영 |

## 6. 정체 감지 및 해결 프로세스

### 정체 판정 기준 (config.py 실제값 기준)

| 40~70% | 예측 배너(노랑) + 모니터링 강화 | SCR-01 |
| < 40% | 정상 모니터링 유지 | - |
